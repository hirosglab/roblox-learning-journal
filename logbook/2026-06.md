## Problem
When running the preliminary consumption script, using the tool caused the Kuih Cincin to disappear instantly without respecting the `task.wait(10.0)` delay. It was unclear whether this immediate deletion was triggered by the Lua code or a platform-default behavior.

仮実装したスクリプトを実行した際、ツールを使用すると `task.wait(10.0)` の遅延を無視してKuih Cincinが即座に消滅しました。この即時消滅が、Luaコードの命令によるものなのか、それともプラットフォームのデフォルトの挙動によるものなのかを切り分ける必要がありました。

## Approach & Deep Dive Verification

### 1. Tool Interaction Dichotomy (Equip vs. Activate)
I isolated the user input states and discovered that clicking the hotbar slot simply toggles the **Equip/Unequip** state handled natively by Roblox (signaled by the default blue UI border). The `tool.Activated` event is strictly triggered when the player clicks the viewport screen *after* the tool is already active.

ユーザー入力の状態を切り離して検証した結果、ホットバーのスロットを再クリックする行為はRobloxが標準処理する**「装備解除（仕舞う動作）」**をトグルしているだけ（UIが青く縁取られる仕様）であると判明しました。スクリプトの `tool.Activated` イベントは、ツールを装備した状態で「画面の適当な場所」をクリックしたときに初めてトリガーされます。

### 2. Runtime Hierarchy Exploration (`Humanoid`)
I verified that while properties like `Handle` and `EatAnimation` exist inside `StarterPack` during edit mode, the player's `character` model and its core component, the `Humanoid` (which tracks health, speed, and handles `LoadAnimation`), do not exist until runtime. During active play testing, I manually located my active avatar model and its `Humanoid` object nested under the `Workspace`.

エディットモード中の `StarterPack` 内には `Handle` や `EatAnimation` しか見えませんが、プレイヤーの `character` モデルや、アニメーション再生を司る心臓部である `Humanoid` は、ゲームが開始されて初めて `Workspace` 内に動的生成される仕様を実際の検証で確認しました。

## What I learned
* `tool.Activated` fires only upon clicking the game environment while a tool is equipped, not when clicking the hotbar UI.
* Live player structures (like `Humanoid`) must be inspected in the Workspace hierarchy *during* active simulation, as they do not exist in the static edit hierarchy.
* A runtime error in Lua halts all subsequent code execution instantly, which can falsely simulate logic skips if system-default tool overrides occur simultaneously.
* Debugging through the Output window is essential for confirming step-by-step synchronization of scripts.

* `tool.Activated` はツールを装備した状態で「ゲーム画面」をクリックしたときのみ発火し、ホットバーUIをクリックしたときは動かない。
* `Humanoid` などの動的なプレイヤー構造は、静的なエディット画面には存在しないため、シミュレーションを実行中に Workspace 階層から直接インスペクト（調査）する必要がある。
* Luaのランタイムエラーはそれ以降のコード実行を即座に停止させる。システム側のデフォルト挙動が同時に発生していると、ロジックをスキップしたように誤認しやすい。
* スクリプトが段階的に同期して動いているかを確認するためには、Outputウインドウでのデバッグが不可欠である。
