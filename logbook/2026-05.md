# 2026-05-24 — Kuih Cincin Optimization: MeshPart Conversion and Tool Infrastructure

## Summary
I converted the finalized Kuih Cincin Union model into a MeshPart to optimize the asset and began implementing the core game infrastructure to turn it into an edible food item. During the import process, I resolved issues regarding texture color overrides and structured the object hierarchy for proper tool functionality.

形状と表面加工が完成したKuih CincinのUnionオブジェクトを、最適化のためにMeshPart（メッシュパーツ）へ変換しました。また、ゲーム内で食べ物として機能させるためのベースとなるTool化の実装に着手しました。インポート時の色データの消失トラブルを解決し、Toolとして正しく動作するための階層構造を整理しました。

---

## Problem
Upon importing the exported `.obj` file via the 3D Importer, the original color data was lost, leaving the mesh completely white. Even after modifying the `Color` or `BrickColor` fields in the Properties panel, the visual appearance of the object did not update in the Workspace.

3Dインポーター経由で`.obj`ファイルをインポートした際、元の色データが消失してモデルが真っ白になりました。Propertiesパネルで`Color`や`BrickColor`を変更しても、Workspace上のオブジェクトの色が変わらない問題に直面しました。

---

## Approach & Solution
I discovered that the 3D Importer automatically assigns a default texture string to the `TextureID` property, which overrides and blocks manual Studio color adjustments. To fix this, I completely cleared the string within the `TextureID` property box and pressed Enter to apply the change. Once the ID was removed, the custom `Color` value immediately reflected on the mesh surface.

3Dインポーターが`TextureID`プロパティに自動生成されたURL文字列を割り当ててしまうことで、Studio側での色変更がブロックされていることが原因だと判明しました。ポップアップではなくプロパティのセルから直接文字列を完全に消去（デリート）してEnterキーで確定したところ、設定した`Color`が即座にメッシュへ反映されました。以前、Unionパーツの時は`UsePartColor`の設定変更を行いましたが、複数処理やインポートを経たオブジェクトの配色管理には固有の仕様（癖）があることを学習しました。

---

## Tool Hierarchical Restructuring
To prepare the object for the player inventory, I initialized a `Tool` object. The 3D Importer creates a nested structure where a `Model` acts as a parent to the `MeshPart`. I learned that Roblox's tool system specifically requires the interactive part to be a direct child of the Tool and named precisely `Handle`.

Therefore, I extracted the inner `MeshPart`, renamed it to `Handle`, placed it directly under the `Tool`, and safely deleted the now-empty parent `Model`.

プレイヤーがインベントリで持てるようにするため、`Tool`オブジェクトを用意しました。3Dインポーター経由だと自動的に`Model`（親） > `MeshPart`（子）という階層になりますが、Robloxの仕様ではToolの直下に`Handle`という名前のパーツが直接置かれている必要があるため、内側の`MeshPart`を`Handle`にリネームしてToolの直下へ移動させ、不要になった空の`Model`オブジェクトを削除しました。これにより、次回からは迷わずスムーズに変換作業が行える知見を得ました。

---

## Result
The infrastructure for the food item is now established:
* **Asset Optimization:** Successfully optimized the Union into a high-performance MeshPart.
* **Color Restoration:** Restored the authentic brown fried-snack color by bypassing the `TextureID` override.
* **Hierarchy Setup:** Configured the correct hierarchy (`Tool` -> `Handle` [MeshPart]) with `Anchored` disabled to allow physics interactions.
* **Step-by-Step Validation:** Verified the tool in a basic test environment to ensure it loads without immediately falling through the map.

食べ物アイテムとしての基礎構造が完成しました：
* Unionからパフォーマンスの優れたMeshPartへの最適化が完了。
* `TextureID`のブロックを解除し、揚げ菓子らしい本来の茶色を再現。
* `Tool` -> `Handle` (MeshPart) の正しい階層を構成し、物理挙動のために`Anchored`をオフに設定。
* テスト環境にて、ツール化したオブジェクトが奈落に落ちずに正常に確認できる状態まで検証を完了。

---

## What I learned
* Exported `.obj` files from Unions do not carry color data, requiring manual re-coloring in Studio.
* `TextureID` values must be completely cleared and confirmed (via Enter) to unlock color rendering on a MeshPart.
* The parent `Model` container generated during 3D import must be dismantled to properly set up a Tool's `Handle`.
* Step-by-step verification in the Workspace is essential before moving assets to `StarterPack` or applying scripts.

より自然な丸みを作るため、Sphereを利用した構造を試しました。

2つの球体を直線上に配置し、それらを同時選択して複製・回転を繰り返すことで、円周状に配置されたリング構造を形成しました。

完成したドーナツ型リングを複製し、中心リングの周囲に6つ配置することで、Kuih Cincinに近い形状を作成しました。

## 2026-05-17 — Kuih Cincin Modeling: Ring Structure Construction and Precision Positioning

## Summary
I built a ring-based structure inspired by the Malaysian snack **Kuih Cincin** in Roblox Studio.

The model consists of a central hollow ring surrounded by six identical ring segments arranged in a circular formation.

マレーシアの伝統菓子 **Kuih Cincin** をモチーフに、Roblox Studioでリング構造のモデリングを行いました。

中心の空洞リングを基準に、同一サイズのリングを6つ円形に配置した構造を作成しました。

---

## What I tried

I created a donut-shaped ring using:

- Cylinder parts
- Negate operation
- Union operation

Roblox StudioでCylinderパーツを使用し、NegateとUnionを組み合わせてドーナツ型のリングを作成しました。

---

## Structure Building

After creating a single ring, I duplicated it and arranged six outer rings around a central ring.

The goal was to approximate the characteristic floral-ring structure of Kuih Cincin.

単体リングを複製し、中心リングの周囲に6つ配置することで、Kuih Cincin特有の花状リング構造を再現しました。

---

## Problem

Manual placement using Move tools was not precise enough.

Even small misalignments caused visible asymmetry in the circular structure.

手動での移動操作では位置精度が足りず、わずかなズレでも全体の対称性が崩れる問題が発生しました。

---

## Approach

To solve this, I directly edited Position values numerically in the Properties panel.

This allowed precise placement of each ring based on calculated coordinates rather than visual estimation.

そのため、PropertiesパネルでPosition値を直接編集し、数値ベースで配置を制御しました。

視覚的な調整ではなく、計算による配置に切り替えることで精度を向上させました。

---

## Base Setup

Center ring:

- Size: (1, 2, 2)
- Position: (-12, 4, 2)
- Orientation: (0, 90, -180)

This central ring was used as the reference point for all surrounding placements.

中心リングを基準座標として、周囲リングの配置計算を行いました。

---

## Calculated Placement Strategy

I used a circular distribution model with 6 equal divisions (60° intervals).

The goal was to maintain symmetry around the center while keeping slight overlap for a handmade Kuih Cincin appearance.

6分割の円形配置（60度間隔）を採用し、対称性を保ちながらも若干の重なりを持たせることで手作り感を表現しました。

---

## Result

The structure successfully formed a connected ring flower shape:

- Center ring + 6 outer rings
- Stable circular symmetry
- Controlled overlap between parts

中心リング＋6つの外周リングによる構造が完成し、円形の対称構造として成立しました。

パーツ同士の軽い重なりにより、Kuih Cincinらしい見た目に近づきました。

---

## Insight

Precise numerical positioning is critical when building symmetrical 3D structures in Roblox.

Manual placement is useful for rough layout, but final alignment requires coordinate-level control.

Robloxにおける対称構造の制作では、数値ベースの位置制御が非常に重要であると学びました。

手動配置は初期レイアウトには有効ですが、最終調整には座標精度が必須です。

---

## What I learned

- Cylinder + Negate is effective for ring creation
- Union simplifies complex geometry into single objects
- Position editing is more reliable than manual movement for symmetry
- Small numerical changes significantly affect overall structure
